# Example: named sources plus broad discovery

Illustrative user brief—not a preconfigured integration:

> Track open-source developer tooling for running models locally. Check the release pages and engineering blogs I provide, and search beyond them for relevant projects or research. Prioritize useful changes for individual developers, including small models and modest hardware. Explain availability, limitations, and hardware requirements when supported by the sources. Deliver every Tuesday and Saturday at 09:00 Asia/Singapore to my chosen channel.

The agent obtains source URLs and the exact channel, clarifies resource limits, and tests its discovery/access paths. Named required sources are checked even if broad search already returns useful stories.

This is one task with two weekly runs, not two unrelated tasks. Follow-ups need material new information. An important repository release should preferably link to the actual release notes rather than a secondary headline.

The user can later request a second, unrelated task. The agent creates a separate brief/history and does not overwrite this task's schedules. Any requested history sharing must define how it affects recipients and recap editions.
